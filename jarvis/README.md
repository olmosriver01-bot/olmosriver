# JARVIS — шахсий AI операцион тизим

«JARVIS AI TIZIMI — 0 dan 100 gacha» қўлланмаси асосида қурилган шахсий дастур: лойиҳалар, ҳужжатлар, хотира (Obsidian тузилмаси), AI роллар, иш жараёнлари, вазифалар ва SOP — бир жойда.

**Асосий жараён:** Топшириқ → манбалар → таҳлил → натижа → хотира → амал → SOP.

## Тез ишга тушириш

Талаб: **Node.js 20+** (macOS: `brew install node` ёки nodejs.org).

```bash
cd jarvis
./start.sh          # биринчи марта: npm install, .env яратади, интерфейсни йиғади ва серверни ишга туширади
```

ёки қўлда:

```bash
npm install
cp .env.example .env    # ихтиёрий
npm start               # = vite build + сервер
```

**Очиш манзили:** <http://127.0.0.1:3333>. Биринчи очилишда кириш паролини ўрнатасиз.

### Mac’да доимий ишлатиш (тавсия)
Репозиторийни **уй папкасига** олинг (Documents/Desktop/Downloads эмас — macOS фон хизматига у ерга киришни чеклайди):
```bash
cd ~
git clone --branch claude/jarvis-personal-ai-nwzj38 https://github.com/olmosriver01-bot/olmosriver.git
cd ~/olmosriver/jarvis
./install-macos.sh            # ўрнатади, ишга туширади, браузерни очади; Mac ёқилганда ўзи ишга тушади
./install-macos.sh uninstall  # автоишга туширишни олиб ташлаш (маълумотлар қолади)
```
Лог: `jarvis/data/logs/`.

### iPhone’дан фойдаланиш
Интерфейс iPhone экранига мослашган. Сервер сукут бўйича фақат шу компьютерда (`127.0.0.1`) очилади. Телефондан кириш учун:
- энг хавфсизи: Mac ва iPhone’га **Tailscale** ўрнатинг, `.env`да `HOST=0.0.0.0` қилинг ва `http://<mac-tailscale-номи>:3333` очинг;
- уй Wi-Fi’ида `HOST=0.0.0.0` ҳам ишлайди, лекин трафик шифрланмайди — очиқ тармоқда ишлатманг.
Safari’да «Share → Add to Home Screen» — илова каби очилади.

## AI провайдерлар
- **Anthropic** (расмий `@anthropic-ai/sdk`, сукут: `claude-opus-5-5`, сервер томонида refusal fallback ёқилган), **OpenAI** (Responses API, `POST /v1/responses`), **Google Gemini** (`generateContent` REST).
- Калитсиз ҳам лойиҳалар, ҳужжатлар, хотира, вазифалар, экспорт ишлайди. AI бўлимида «Провайдер уланмаган» деб кўрсатилади; сохта жавоб берилмайди.
- Калит: Созламалар → AI провайдерлар (серверда AES-256-GCM билан шифрланади) ёки `.env`.
- «Калитни ҳақиқий API орқали текшириш» тугмаси провайдердан моделлар рўйхатини олиб, танланган модел мавжудлигини текширади. OpenAI/Gemini модел номлари тез ўзгаради — шу тугма билан текширинг.
- **Обуна ≠ API:** ChatGPT Plus / Claude Pro / Gemini Advanced API ҳуқуқини бермайди; API калити ва тўлов провайдернинг developer платформасида алоҳида.
- Харажат назорати: ойлик бюджет, кунлик ва дақиқалик лимит; Anthropic нархлари киритилган, OpenAI/Gemini нархларини Созламаларда киритинг.

## Маълумотлар, backup ва тиклаш
- Ҳамма маълумот `jarvis/data/` (ёки `JARVIS_DATA_DIR`) ичида: `jarvis.db` (SQLite), `uploads/`, `backups/`, `secret.key`.
- **Автоматик backup:** ҳар куни (охирги 14 таси). Тиклаш ва Markdown импортдан олдин ҳам автоматик backup.
- **Қўлда backup:** Созламалар → Backup → «Ҳозир backup олиш» ёки `npm run backup`.
- **Тиклаш:** Созламалар → Backup → «Тиклаш» (тасдиқ: `ТИКЛАШ`), ёки файлдан, ёки терминалда:
  ```bash
  npm run restore                      # backup’лар рўйхати
  npm run restore -- jarvis-....zip    # тиклаш (олдинги ҳолат pre-restore сифатида сақланади)
  ```
- `secret.key` ни алоҳида сақланг: усиз backup’даги API калитлари очилмайди (калитларни қайта киритиш кифоя, бошқа маълумот йўқолмайди).
- Бошқа компьютерга кўчириш: `data/` папкасини нусхаланг.

## Obsidian
- **Экспорт:** Хотира → Markdown / Obsidian → .zip; очиб, Obsidian’да «Open folder as vault».
- **Импорт:** .md ёки .zip; `jarvis_id` бўлса янгиланади (эски версия сақланади).
- **Тўғридан-тўғри синхронлаш:** vault папкасининг тўлиқ йўлини киритинг (JARVIS ишлаётган компьютерда). Фақат шу папка ичида ишлайди, symlink орқали чиқмайди; ташқарида ўзгарган файл устидан ёзилмайди — зиддият кўрсатилади; устидан ёзишдан олдин нусха `data/backups/vault/`га.

## Режалаштирувчи
JARVIS сервер жараёни ичида ҳар 30 сонияда ишлайди (Asia/Tashkent, UTC+5). Сервер/компьютер ўчиқ бўлса иш бажарилмайди ва «ўтказиб юборилди» деб белгиланади; қайта ёқилганда охирги слот бир марта «кечикиб» бажарилади. Ҳар бир слот базада UNIQUE калит билан ҳимояланган — такрорий бажарилиш бўлмайди. Mac ухлаганда ҳам ишламайди — доимий ишлаши учун серверда ёки `pm2`/launchd орқали ишга туширинг.

## Тестлар
```bash
npm test             # 36 та backend тести (сохта провайдер ва маҳаллий сохта HTTP сервер билан)
npm run typecheck
# Браузер тести (Chromium/Playwright керак):
JARVIS_DATA_DIR=/tmp/jarvis-e2e JARVIS_ENABLE_MOCK=1 PORT=3410 npm run serve &
node tests/e2e-browser.cjs /tmp/jarvis-shots http://127.0.0.1:3410
```
**Муҳим:** тестлар MOCK провайдер ва сохта HTTP сервер билан ўтади. Бу ҳақиқий OpenAI/Anthropic/Gemini API’лари ишлаганини исботламайди — ҳақиқий калит билан «Калитни текшириш» тугмасини босиб текширинг.

## Хавфсизлик
Парол (scrypt), HttpOnly/SameSite=Strict сессия, CSRF сарлавҳаси, кириш уринишлари чеклови, калитлар шифрланган, ички тармоқ URL’лари блокланган (SSRF), ҳужжат ичидаги кўрсатмалар маълумот сифатида ўралган, саватча ва тасдиқли ўчириш, амаллар журнали. Паролни унутсангиз: серверни тўхтатинг, `data/jarvis.db` даги `settings` жадвалидан `auth.password` қаторини ўчиринг (ёки `.env`да `JARVIS_PASSWORD` бериб шу қаторни ўчиринг) ва қайта ишга туширинг.
